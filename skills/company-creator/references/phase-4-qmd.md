# Phase 4: Configure qmd Search

qmd provides hybrid BM25 + vector search over compiled wiki pages. The Librarian
agent queries it via MCP (preferred) or CLI fallback. The index lives at
`~/.cache/qmd/<brand>/` and is never committed to git.

Replace `<brand>` with your company slug.

---

## 1. Create the .qmd directory

```bash
mkdir -p companies/<brand>/.qmd
```

## 2. Create qmd.yml

One collection per niche. Collection name must match the niche slug exactly.
Paths are relative to the repo root.

```bash
cat > companies/<brand>/.qmd/qmd.yml << 'EOF'
# <brand> qmd collections
# One collection per niche. Collection name MUST match niche slug.
# Paths are relative to the repo root (companies/<brand>/).
# DO NOT edit this file directly; use assets/scripts/sync-qmd-collections.ts
# which reads COMPANY.md:niches and keeps this in sync.

collections: {}

# editor_uri preference for click-through from search results
editor_uri: "vscode://file/{path}:{line}:{col}"
EOF
```

The `collections` block starts empty. You'll add the first collection in Phase 5
when you create the first niche.

## 3. Wire qmd in .paperclip.yaml

The `mcp_servers.qmd` entry should already be present from Phase 1. Confirm:

```bash
grep -A3 'mcp_servers' companies/<brand>/.paperclip.yaml
```

Expected:

```yaml
mcp_servers:
  qmd:
    command: qmd
    args: [mcp]
```

If it's missing, add it now. The MCP server uses stdio transport by default.
For a long-lived shared daemon, switch to HTTP transport:

```yaml
mcp_servers:
  qmd:
    url: http://localhost:8181/mcp
```

Start the daemon separately with `qmd mcp --http --daemon`.

## 4. Verify qmd is installed

```bash
qmd --version
```

If not installed, follow the qmd installation docs for your platform.

## 5. Dry-run the sync script

After Phase 5 adds the first niche, run this to verify the collection config
will be generated correctly:

```bash
bun assets/scripts/sync-qmd-collections.ts \
  --company-slug <brand> \
  --dry-run
```

The script reads `COMPANY.md:niches` and writes one collection block per slug
into `.qmd/qmd.yml`. Dry-run prints the diff without writing.

## 6. CLI fallback for Librarian

If Paperclip rejects the MCP schema, Librarian can fall back to the CLI:

```bash
qmd query "<question>" -c <niche-slug> --json --min-score 0.3 -n 15
```

Document this fallback in the Librarian agent's AGENTS.md so it knows to try
the CLI when the MCP tool is unavailable.

Phase 4 complete. qmd is configured. Move to Phase 5 to add the first niche.
